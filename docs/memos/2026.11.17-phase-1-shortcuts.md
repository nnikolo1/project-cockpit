# Phase 1 shortcuts

Date: 2026-11-17

Corners cut to get a usable pilot. Each lists why, the limit, and the first step to do it properly.

| Shortcut | Why | Limit | First step |
|---|---|---|---|
| One identity for all roles | A pilot needs no extra accounts | Protected labels cannot be enforced, only agreed (ADR 0003) | Give the Orchestrator its own GitHub login, then install the policy workflow |
| Reactive enforcement only | GitHub has no per-label permissions | A wrong label shows for minutes; the cockpit ignores it meanwhile | Branch and repository permissions per identity (roles memo) |
| No module-creation screen | The config file is small and reviewable (ADR 0005) | Adding a module means editing a file | Offer creating the `module:<id>` label from the page |
| Review marks in the browser only | Avoids any server-side store (ADR 0007) | Not shared across browsers or people | Keep marks as a repository file or issue comments, if sharing is needed |
| Code metrics from a snapshot | The cockpit must not become a tool chain (ADR 0008) | Numbers can be stale; sub-modules show "not wired" unless the producer emits them | Have the producer write per-sub-module entries and refresh on a schedule |
| Ranking only in the page | It was needed for display first (ADR 0006) | An unattended agent cannot ask the cockpit for the next task | Move the comparison into `logic.py` and expose it as an API endpoint |
| Simulated Orchestrator (`--simulate-orchestrator`) | Lets the demo show "takes it" and "completes it" | Buttons act as the Manager; only for demos | Remove once a real Orchestrator runs |
