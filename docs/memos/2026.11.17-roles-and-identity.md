# Roles and identity

Date: 2026-11-17

## The three roles
From [the constitution](../constitution.md):
- **Manager**: the human. Only the Manager releases tasks, sets priority and deadlines, and cancels.
- **Orchestrator**: an AI agent between the Manager and the Workers. It assigns tasks, validates results, merges to the main branch, and may create tasks and change their other attributes. It may not do the four things reserved to the Manager.
- **Worker**: an AI agent that does one task, each in its own git work tree. Several can run at once.

The constitution adds that these write rules should be enforced by an identity and access system, not by an instruction to a language model.

## Phase 1: one identity
Today everyone acts as the same GitHub login, the Manager's. The cockpit therefore cannot tell who really set a label. It still applies the rule (a protected label counts only if the Manager set it, see ADR 0003), but with one login every change looks like the Manager's. The rule is followed by agreement, not enforced.

## What separation would need on one machine
- A separate login per role: a separate OS user, or a GitHub machine account (or app) for the Orchestrator and for Workers, each with its own `gh` authentication, so that GitHub records a different actor.
- Branch protection on the main branch, so that only the Orchestrator's identity can merge and Workers can only open pull requests.
- The policy workflow from `kit/` installed with the Manager's login as its `MANAGER` variable, to revert protected labels set by anyone else.
- Repository permissions that give Workers the least they need (for example, no admin rights, so they cannot change the workflow or the protection).

## Honest limits
- Reverting is after the fact; there is no way to stop a collaborator with write access from setting a label, only to ignore and undo it.
- Separate OS users on one machine share a disk; a determined agent running as the Manager's user can read the Manager's credentials. Real separation needs credentials that the agents' processes cannot reach.
- Detection of agent-written rule changes (ADR 0007) is a convention-based hint until identities differ.
